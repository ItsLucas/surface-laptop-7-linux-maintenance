## 最终版本补充（以本节为准）

完整功能版本需应用kernel/series中的3份补丁及iptsd/series中的2份补丁。kernel/0003仅改变设备树，本次没有重编内层内核或模块；完整启动镜像复用原内层内核并追加GTCH设备树，另行MOK签名。最终内核deb仍为7.2.0-5.5+sl7.1，当前默认使用独立的/boot/sl7/7.2.0-5-sl7-spi-touchscreen-test/kernel.efi，不能仅恢复原deb就宣称触屏也恢复。匹配initrd和完整镜像已纳入恢复包boot/，哈希见CURRENT-ARTIFACTS.json。

最终iptsd源码在sources/iptsd-sl7-click-fixed-source.tar.gz；也可从上游v3.1.0依series重建。版本3.1.0+sl7.2-1包含触点/按钮修复和升级脚本修订；该二进制与三轮计数测试使用的修复版一致。最终打包脚本在iptsd-packaging/DEBIAN：仅首次安装执行hidraw add探测，升级时重启已有服务，避免设备初始化时的探测冲突。不要用历史3.1.0+sl7.1的控制文件覆盖它。

下文记录当日基础包的原构建流程；用于完整重建时以本节的补丁数、独立启动路径和最终打包文件为准。新构建仍应使用独立release/模块目录、现有公钥信任链、重新签名和一次启动验证。

**这是当前已验证版本的重建说明，不是对任意新内核的一键升级承诺。**

精确输入如下：

| 输入 | 版本 |
|---|---|
| Ubuntu linux-source / buildinfo | `7.2.0-5.5` |
| 输出 release / 包版本 | `7.2.0-5-sl7` / `7.2.0-5.5+sl7.1` |
| GCC/G++ | `15.3.0-3ubuntu1`，官方原构建为 `15.3.0-2ubuntu1` |
| Rust | `rustc-1.95=1.95.0+dfsg-0ubuntu1` |
| bindgen | `0.72.1-1` |
| Clang/LLVM | `21.1.8-6ubuntu1` |
| Stubble | `13-1`，从 deb 解包使用 |
| dracut-core / kmod | `112-6` / `34.2-2ubuntu3` |
| iptsd 源码 | `3663e96e758145801c3cb1ce7c72f362d0d4a5f5` |

恢复包 `build-inputs/` 保存原 Ubuntu source、buildinfo 和 Stubble deb；维护包 `sources/` 保存 iptsd 两个源码快照。完整系统依赖版本见 inventory；恢复包不是包含所有编译依赖的离线 APT 镜像。

在新的工作目录中复现原项目布局：`kernel-source/linux-source-7.2.0`、`kernel-build/sl7`、`kernel-package-root`、`stubble-package`、`artifacts`、`logs`。先解开源码 deb 内的 tar.bz2，按 kernel series 顺序应用补丁，再将 `config/kernel-source-overlay/` 的三个公开文件放到源码相对位置。复制 `config/kernel-7.2.0-5-sl7.config` 为输出目录 `.config`。该覆盖层仅用于重现当前版本；换新 Ubuntu 基线必须重新取对应 buildinfo。

原内核构建命令为：

```bash
nice -n 10 make -C kernel-source/linux-source-7.2.0 \
  O="$PWD/kernel-build/sl7" LOCALVERSION=-5-sl7 \
  RUSTC=rustc-1.95 BINDGEN=bindgen -j8 Image modules
```

另需编译 Romulus13 DTB 和 `vmlinuz.efi`。完整构建使用公开模块证书内建信任，不把私钥复制到源码树；模块在 staging 完成 strip 后，由 root 使用独立私钥批量签名。

将 `build/current-7.2.0-5-sl7/` 中的原脚本复制到该工作目录根部，再审阅其路径。`assemble-combined-kernel.sh` 的顺序为 staging 模块 → strip → 签名 → zstd → depmod → 签内层 EFI → Stubble 包入 DTB/HWID → 签外层 EFI。它不是系统安装程序；当前脚本仍引用原签名工具 `/usr/src/linux-headers-7.2.0-5-generic/scripts/sign-file`，重建环境须提供该工具，换版时应采用目标构建树生成的 sign-file。

`depmod -e -E` 在 kmod 34.2 对 Rust 扩展符号表给出过 101 个误报。当前验证器读取内核实际优先使用的扩展表，核对 358,295 个导入项全部匹配。新版本不能照抄“忽略 101 条”的规则：必须重新解释每一条，普通 depmod 应干净，任何新 unknown symbol/真实 CRC 不匹配都需处理。

包的 DEBIAN 脚本与集成文件在 `kernel-packaging/`。将已签镜像放入 `/boot/sl7/7.2.0-5-sl7/kernel.efi` 的 staging 路径、放入 config/System.map 和新模块树，再按最终 payload 重算 md5sums、Installed-Size（当前原包未设置该字段，后续应补齐）后用 `dpkg-deb --build --root-owner-group` 生成包。本次实际包 SHA256 在恢复包清单中，不要求重编产物字节级一致：构建时间、环境等因素可能变化，仍须重新签名和验证。

iptsd 的构建设置是 G++15、prefix `/usr`、release、`b_lto=false`、`wrap_mode=nodownload`、`debug_tools=calibrate,dump,perf`。依赖应包含 `libmsgsl-dev` 和 `systemd-dev`；不要把 GNU 科学库 `libgsl-dev` 误当作 Microsoft GSL。构建后使用 DESTDIR staging，确认 systemd unit、udev rule、sleep hook 都存在，再使用 `iptsd-packaging/DEBIAN` 打包。个人最终校准留在 `/etc/iptsd.d/`，不能被替换成早期社区阈值。

已有安装包可直接用于同一系统恢复；本文件描述重建并不授权覆盖正在运行的内核。新产物要按更新计划完成验签、独立安装和试启动。

根文件系统中的 initrd 应使用当前 dracut 生成，并带入已签的 `spi_hid spi_geni_qcom gpi` 及 Wi-Fi 板级覆盖。保持 Ubuntu X1E 的固件/ADSP 初始化逻辑。归档的旧 `sl7-kit-firmware` 是 initramfs-tools hook，不应当作 dracut 插件直接调用。
